> 🔴🔴 **本项目最贵的一条教训**：两条映射都是「按字面语义推断」定的，
> 看着合理（`Cracking`→裂纹、`Off_platform`→脱离平台，字面对得上），

### 🔴 补齐的真实缺口：推理模型从未落盘
`train.py` 跑完只写 json，**模型完全没存**。下游预测一张新图只能重跑

### 🔴🔴 最重要的一条护栏：部署件不能报 99.73%
99.73% 来自 **group-aware 5 折交叉验证**（每张图的预测来自没见过它的模型）。
落盘的部署件是**全量 1,912 张重训**的（部署就该用全量，CV 版本每张只用 80%）。
在它上面重算 macro-F1 = **训练集准确率**，必然虚高。
与 P0 阶段「模型选择误用测试折」同类，必须防复发。
→ `infer.evaluate()` **直接抛错拒绝执行**，只允许引用折外99.73%。已做反向自检 ✅。

### 🔴🔴 踩到的最隐蔽的坑：部署件上的高置信度是**自证**
初版把拒答阈值拍成 0.60，在部署件上跑 5 张 demo 全对、概率全 0.99+，拒答一次没进。
更能骗人的是：一张**折外被误判**的图（真值 Cracking / 折外判 Warping / 概率仅 0.6343），
在部署件上给出 **Cracking 0.9928** —— 因为它训练时见过这张图。
→ **部署件上的置信度对新图毫无参考价值**。必须用**折外**模型标定。

### 拒答阈值实测标定（0.60 → **0.90**）
```
正确(n=1906) 最高概率 mean 0.9957 median 0.9999 min 0.5576
错误(n=6)    最高概率 mean 0.6910 median 0.6646 min 0.4919
→ 置信度确实能区分对错（差 0.30）

th=0.60 回答 99.8% 拦下错误 33.3%  ← 会误伤（正确样本最低仅 0.5576）
th=0.90 回答 98.6% 拦下错误 83.3%  回答中正确率 99.95%  ← 采用
th=0.999 回答 78.5% 拦下错误 100%   覆盖率代价太大
```
⚠️ **高置信度也不等于正确**：0.90 下仍有 1/6 错误带着 ≥0.90 溜过去。
⚠️ **只有 6 个错误样本**，统计基础极薄，阈值只能当起点，不是定论。

## 唯一真问题：上下文预算

P0 的 `MAX_CONTEXT_CHARS=10000` 硬编码在 `build_context`，不能改。
视觉证据体量 7.2k~28.3k。**实测贪心截断会挤掉整块**：

```
Layer_shifting 送 5 块 → 只剩 KB008（KB050/052/065/009 全丢）
Off_platform   送 6 块 → 只剩 KB101/102/103（KB002/028/067 全丢）
```

被挤掉的恰是次要映射与易混淆项，且模型**不知道**它们被丢了 → 静默丢证据。

方案 = **max-min轮转填充**。实测 5 类全部 KB 保留、不触发二次截断：

| 类 | KB 保留 | ctx | 根因覆盖 |
|---|---|---|---|
| Cracking | 2/2 | 7,316 | 10/10 (100%) |
| Stringing | 3/3 | 9,068 | 14/18 (78%) |
| Layer_shifting | 5/5 | 9,732 | 14/33 (42%) |
| Warping | 3/3 | 9,898 | 13/18 (72%) |
| Off_platform | 6/6 | 9,828 | 16/46 (35%) |

**54% 是 10k 硬上限的诚实结果**，非算法浪费：单条根因最大 3,453 字（KB024 c4）；
根因级拼装与原文仅差 91~662 字 → 没有可省的冗余。

❌ 试过「按剩余体量比例分配」——**更差**：Layer_shifting 只花 6,768/10,000，
且最重要的 primary KB008 只拿 1 条根因（下一条比预切额度大就直接 break）。
轮转填充推到 9,732 且 KB008 拿 3 条。

## 抓到的 4 个 bug

1. 🔴🔴 **LangGraph 静默丢弃 schema 未声明的入参**（最危险）
   `AgentState` 是 `TypedDict(total=False)`，未声明的 `image_paths` **直接消失、不报错**
   → 有图也走文本路径，返回值「看起来都正常」。
   最小复现：`StateGraph(S2).invoke({'query':..,'image_paths':[..]})` → `{'query':..}`。
   **只能靠断言 `route=="vision"` 抓到**，看字段齐不齐抓不到。
2. **多图合并所有 KB 给互斥建议**：3 张不同类别的图 → 12 个 KB / 3 套互斥建议。
   **类别是互斥的诊断结论，不是可并集的信息**。改为只取主类别 + 显式告知冲突。
3. **验收断言写错**：`top_cosine` 两条路径语义不同（文本=真实余弦 0.3355 / 视觉=-1.0），
   写成恒等断言 → 文本路径必然 FAIL。
4. **预算记账漂移**：固定 `HEADER_RESERVE=120` → 实际和 10,146 > 10,000，二次截断照旧。
   改为按 `build_context` 真实格式逐字复算。

## P0 既有 bug（用户批准后已真修）

`vector_index.load_fitted_embedder()` 硬编码读 **cause 级**索引路径，
kb 模式下 fitted 在 `faiss_index_kb.tfidf_svd.pkl` → 查询侧拿 `None`
→ 用单条 query 重新 fit 一个迷你 TF-IDF+SVD。

**修法**（P0 冻结区，经用户批准）：
- `load_fitted_embedder(path=None, strict=False)` 按索引路径取 + 补 `Path` 导入；
- `_FITTED_EMBEDDER` → `_FITTED_EMBEDDER_CACHE` **按索引路径分桶**
  （两索引 vocab/SVD 基不同，单变量会让一个 mode 复用另一个的 fitted）；
- `_embed_query(..., fitted_path=None)` 缺失即 `ValueError`；
- `HybridRetriever.faiss_path` 透传 2 处调用点。
验收脚本 `patch_offline_embedder()` 旁路**已删**，换`assert_no_bypass_needed()`
**反向自检**（修复被回退直接 AssertionError）。A~F 重跑 **ALL PASS**。

### 🔴 归因两次修正（别照抄旧结论）

原写「→ 抛 `TruncatedSVD n_components` 越界」。实测（`exp/_tmp_bug_mechanism.py`）
有**两条**后果：

| 情形 | 机制 | 表现 | 性质 |
|---|---|---|---|
| (a) query 短，TF-IDF 只切 1 个 token | `n_components=0` | `InvalidParameterError: Got 0` | **吵闹**，原判断对 |
| (b) query 长，切出多个 token | fit 出 **vocab=3** 迷你模型，查 16367 词表索引 | 维度同为 1024 → FAISS**不报错**，静默返回假相似度 | **安静**，危害更大 |

(b) 实测：迷你向量 top1 = KB002 Not Sticking to the Bed cos=0.3613，
正确答案是 KB006 Stringing or Oozing。与 `assert_backend_consistent`
拦的同一类 → `strict=True` 主动报错是必要的。

> **教训**：又是一次「按语义推断 bug 机制」被实测推翻（前一条是映射层
> 「字面对得上≠ 现象对得上」）。`InvalidParameterError` 只在**单词 query** 下出现，
> 稍长 query 根本不报错。**只测一个 case 就下机制结论 = 测得不够。**

### ⚠️ 修好后暴露的独立缺陷（未修，需另立任务）

离线兜底 TF-IDF 对**中文 query 完全失效**：
索引语料是英文（`KB001 text='Not Extruding at Start...'`）+ 默认
`token_pattern` 不做中文分词 → `nnz=0` → 查询向量**全零**；
BM25 路被同一分词器拖累 → **双路皆零**
→ `retrieve("打印件表面有拉丝")` 返回 KB001~KB005 **字母序**，score 仅 0.013 量级。
**中文场景必须配 `DASHSCOPE_API_KEY`**（生产本就如此），或换中文分析器重建索引。
**P0 的 54.37% SOTA 不受影响**（带 key 测的，走 DashScope embedding）。
但这解释了「无key 环境下 P0 文本路径 top_cosine 恒 0」——不是 bug，
是中文 query 在英文 TF-IDF 索引上本就无信号。
