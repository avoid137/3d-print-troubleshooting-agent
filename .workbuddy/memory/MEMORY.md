## 通用坑（脚手架级）

🔴 **长时间任务：进程"在跑"≠ 有进展**。必须按**字节增长趋势**判断，
不能只看进程状态（实测 curl 卡死 1.5 h、7 个进程都在却零传输）。
🔴 **curl 必须加低速自杀** `--speed-limit 10240 --speed-time 60`——
`--retry` 只管连接失败，速率归零会**永久阻塞**。
🔴 **`curl -C -` 与 `-r` 不能共用**（实测 `option -r: is badly used here`，
且**静默不续传**、rc=0 也不报错）→ 手工算区间 `[lo+已有, hi]` 下到 `.seg` 再追加。
🔴 **`py_compile` 抓不到 NameError**（删了定义仍能过编译）→ 提交前必跑
`pyflakes <file>`，这类"改 A 漏 B"肉眼抓不到。
🔴 别用 `tmp.unlink()` 清残片（被安全策略拦截）；`curl -o` 本身覆盖截断。
🔴 限流时 rate=0 会 ZeroDivisionError 崩掉 → `rate>0` 才算 eta。
🔴 **别拿短时峰值当结论**（已犯 3 次）。⚠️ **别用 `except: pass` 掩盖导入失败**
（`scripts/` 下 `sys.path[0]` 是 `scripts/` →白排查半小时）→ 用 `importlib.util.spec_from_file_location`。
⚠️ **`0.99and` 会被当小数点字面量**（只发 SyntaxWarning，py_compile 不报错）。
`global` 写在 `parse_args()` 之后 → SyntaxError；别凭记忆写 `old_string`。
`nohup &` 会被回收 → 用 `run_in_background` + `python -u`。
⚠️ Windows 上 `stdbuf` 不可用（`libstdbuf.dll` 找不到）→ 别在 Windows 用它。
🔴 **网络**：并发不是越高越好（18 并发触发限流，**6 并发稳态最快**）；`modelscope.cn` 不可达不必再试；
✅ 唯一权重源 = **`hf-mirror.com`**。🔴 Kaggle `totalBytes` **不可作完整性基准**
→ 判据 = zip 条目数 + CRC + 各类张数。Kaggle 公开集**匿名可下**，
但 🔴 **HEAD 请求返回 404**（端点只支持 GET，会误判成"下不了"）。

## 方法论纪律（本项目最值钱的部分）

**① 字面对得上 ≠ 现象对得上。** 两条映射都按字面语义推断、看着合理，**看图后全错**：
Cracking 20/20 是层向贯穿+撕裂纤维+层间错位 → 实为 **Delamination** → 主映射 **KB009**；
Off_platform 20/20 画面**无成形件**、材料堆成乱丝 → 是 **Spaghetti**，而
**KB101 标题就是 `Spaghetti (Print Detached from Bed)`** → 不能因「标题像别的」降级为易混淆。
⚠️ KB 标题可能含**旧版的、正当的别名**。⚠️ DC-02R 构图 = 整台打印机 + 底下一小块件，
**只看缩略图会误判，必须放大。**

**② 判「模型是否走捷径」不能只看「该线索单独能到多少分」，必须主动移除它看分数掉多少。**
19 维低级像素统计就能拿 71.5% → 我据此**推断**「99% 反映的是识别拍摄批次」→ **被干预实验推翻**
（去背景 0.00pp）。**两个结论可以完全相反。** 延伸：遮挡指标**必须用连续值**（概率相对降幅），
0/1 翻转在 5 分类里只有两档，全是 0 只说明「没翻转」。

**③ 落地前必须核对「实验口径」与「部署口径」一致。** D9 里A/B 用默认权重、部署用 `balanced`，
差 0.13pp 且**改变了结论方向**。没核对就重建部署件 = 用没跑过 A/B 的参数去落地 A/B 的结论。

**④ 静默算错比报错危险得多。** 本项目 8 个 bug **全部**是「不报错、数字错」型，含类型陷阱、
解包顺序错、**指标语义反向**、训练集内自评当折外、报告硬编码数字、**护栏在合法配置下误报**。
🔴 对策：① 关键指标**先写死判定规则再跑**；② **反向自检**（`assert_can_fail`）；
③ **单测输入必须与生产同类型同形状**；④ 报告数字动态生成；⑤ **护栏必须覆盖所有合法配置**，否则会被当噪音关掉。

**⑤ 🔴 最贵的一条：实验测了「正例」不等于测了「反例」。** D9 只测「正常件能否被认出」，
**没测「缺陷件会不会被一起认成正常」**——而后者才是上线后最致命的。
🔴 **判据**：任何「新增一类」或「加判别分支」的方案，必须同时测**双向吞噬**（新不吞旧、旧不吞新），
只测一个等于没测。与②同源——**都要问「去掉它会怎样」，不能只看「加上它好不好」**。
