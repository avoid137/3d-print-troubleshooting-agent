### 关键发现 1：pHash 单独用不够（必须双检）

SSRN 7395570（4 个医学影像数据集 × 5 seed × 5 fold = 25 次配对跑）用 HAM10000 **真实病灶ID** 验证发现：**pHash 只召回 3.3% 的真实同病灶图像组**。

→ 因此去泄漏方案**升级**为：**pHash 粗筛（dHash ≤5 保守档）→ DINOv2 冻结特征精筛（补不同视角的同实物）→ 阈值人工标注自标定（不照抄 5）→ 连通分量聚组 → StratifiedGroupKFold**。group-aware 作**主口径**，stratified 仅作对照算差值。
→ 该文还证明：泄漏影响是**数据集特定**的，不能预设大小，必须实测。

### 关键发现 2：方法上应做三级对照（替代只跑全量微调）

两处独立证据：
- **同领域**：Bast et al. 2026, IJAMT 144:2047-2059（DOI 10.1007/s00170-026-17844-w，2026-04-10）—— FFF 缺陷检测，用**预训练 ResNet-50 只提特征 + kNN**（不微调），4 类含无缺陷，**各类 F1 0.757~0.990，加权平均 0.812**。
- **跨领域**：植物病害 PlantVillage→PlantDoc，**冻结 DINOv2 线性探针 51.1%，比全量微调 EfficientNet-B0 高 +23.4pp**；全量微调使跨域 50.6%→29.4%（即微调破坏预训练特征、损害泛化）。海洋物种研究同样显示 DINOv2 LP 与全量微调持平但参数少 4 个数量级。
- **反例（务必记住）**：字体 394 类细分类，线性探针仅 **36.6%**，远低于 LoRA 98.7% → **线性探针不一定够用，必须实测不能假设**。

→ 定为L1（冻结+kNN，分钟级）/ L2（冻结+线性探针，分钟级）/ L3（全量微调 EfficientNet-B0）三级对照，每级跑两套折划分 = 6 组结果。L1/L2 几乎不花时间却把实验升级成有消融的对照研究。组内差异 < 2pp 一律判「等价」（P0 的 ±7pp 纪律）。

### 🔴 防线自检抓到一个真 bug（这正是第五道防线的价值）

`RuntimeCounter.record(ok: bool)` 把 `ok=False` 一律记到 `failed`，
**导致 `empty_rate` 恒为 0 → 防线 3 永远不会触发**，是典型的「永远通过的检查即装饰」。
若不做反向自检，这个缺陷会一直藏着，训练时数据有问题也不会报。

**修复**：改为两个语义不可混淆的显式方法 `record_empty()` / `record_failed()` / `record_ok()`，
并分别检查 `empty_rate` 与 `failed_rate`（原先只查 empty）。同步修了 `train.py` 的调用。

## 第八轮：D2 去泄漏（抓到 3 个 bug，最险的一个是静默降级）

### 第一次跑：MemoryError

`imgs.append(im.convert("RGB").copy())` 把 1,912 张 **3072×2048 原图**全解码进 list ≈ **21 GB**。
修法：哈希与 DINOv2 本来也只需 224px → 边读边缩（`im.draft("RGB",(512,512))` + resize 224）、
原图立刻丢弃，峰值降到 ~350 MB。顺手把 O(n²) 两两比较向量化
（`np.bitwise_count` popcount，**验证与原 `hamming()` 0 处不一致**；特征侧用 `np.triu_indices`）。

### 第二次跑：特征精筛被 `except Exception` 静默吞掉（🔴 最危险）

日志只给了一行警告：
`⚠️ 特征精筛不可用（AssertionError: Input height (224) doesn't match model (518)），仅用哈希结果`
于是「特征命中 **0** 对」看起来像「数据集没有语义重复」，**实际是精筛根本没跑**。

而精筛是方法论核心 —— SSRN 7395570 实测 **pHash 单独仅召回 3.3% 真实同病灶组**。
若就此收工，group 会偏多 → 去泄漏不彻底 → 指标虚高，且**报告里看不出来**。

**根因**：`_prep` 硬编码 `Resize((224,224))` + 手写 ImageNet mean/std，
而 DINOv2 ViT-B/14 原生 **518**（pos_embed 1370 token = 518 patch + 1 cls + 851 register）。
两个毛病都违反既有纪律：尺寸硬编码 + **手写归一化**（应只取 `resolve_data_config`）。

**修法**：
1. `FeatureExtractor.__init__` 从 `resolve_data_config` 读 `input_size`/`mean`/`std`，不再硬编码
2. 初始化末尾加**冒烟**：拿张空白图走一遍 `__call__`，维度不对直接 `GuardError`
3. **删掉 `except Exception`**，让精筛失败直接崩；并新增断言：粗筛有命中但精筛补 0 对 → `GuardError`
   （「精筛没跑」与「确无重复」必须可区分）
4. 特征比较向量化（`np.triu_indices`）

### 顺带发现：特征阈值 0.92 定得太低

实测 **Warping 同类 8 张**两两余弦：min=0.931 / mean=0.957 / max=1.000。
→ 阈值 0.92 会把大量「同类但不同实物」误判为同一 group。
这正是 `--calibrate` 存在的理由：**阈值必须用本数据集实测分布定，不能照抄文献**。

### 纪律复盘

本轮三个 bug 里有**两个是同一种病**：`except: pass` / `except Exception` 掩盖失败，
让检查变成「永远通过的装饰」——正是防线 5 的原话。
**这个项目里凡是 try/except 都要追问一句：它吞掉的是不是我想看见的失败？**

## 第十轮：D2 定稿 + D3 三级对照启动（本轮）

### D2 去泄漏定稿：`data/p1_folds.json`已产出并交叉验证
**关键决策：pHash/dHash彻底降级为「只读诊断」，不再参与 union。**
实测三条硬证据（`exp/p1_d2_impure_diagnosis.json`）：
1. **省不到算力**：DINOv2 特征是 per-image 的，粗筛一张都省不掉。
   而粗筛 supposed 要省掉的 N² 余弦计算实测只要 **40.7 ms**（1912² 矩阵乘 15.9ms + 上三角阈值 24.8ms）。
2. **精确率极低**：pHash≤5 命中 2,539 对里真重复只有 163 对（161 前缀 + 2 余弦同意），
   **误合并 2,376 对 = 94.3%**。
3. **传递闭包放大**：这 2,376 对经并查集放大后产出 **19 个跨类污染 group**，正好撞上硬断言。

→ 19 个污染组的根因就是「pHash 粗筛 + 传递闭包」，不是前缀规则（前缀实测零跨类）。
**D2 最终口径**：前缀（确定性 GT，81组242张，零误判）∪ DINOv2 余弦≥0.995（145对）
→ 1,749 group、折叠 163 张、最大组 3、**跨类污染 0**、前缀 GT 召回 **81/81=100%**。

**D2 实证价值**：普通分层下 **78/1749 group 被拆散到多折，涉及 234 张（12.24%）**——
这就是必须做去泄漏的量化理由。泄漏幅度（训练后）= stratified − grouped = **−0.18pp**（L2）。

### 🔴 本轮最重要的方法论教训：判定「捷径」必须做干预实验
我先做了审计，发现**仅凭 19 维低级像素统计就能拿 71.5% macro-F1**，
各类背景色两两分明（Warping/Off_platform 绿打印床 R0.36G0.61 vs 其余灰白 R0.44G0.46），
于是**推断**「98% 反映的是识别拍摄批次而非缺陷形态」。

**这个推断是错的**，被 `exp/d3_intervention.py` 实测推翻：

| 干预 | L2 macro-F1 | 相对 V0 |
|---|---|---|
| V0 原始全图 | 0.9977 | — |
| V1 中心 60% 裁剪 | 0.9882 | −0.95pp |
| V2 边缘中位数去背景 | 0.9977 | **0.00pp** |
| V3 去色 + 去背景 | 0.9944 | **−0.33pp** |

→ **颜色/背景捷径对高分的贡献只有 0.33pp**。71.5% 只是「19 维像素统计能到的高度」，
  ≠ EfficientNet 1280维特征的依赖度。**高 macro-F1 不是虚高。**
**纪律新增**：判定捷径不能只看「该线索单独能到多少分」，**必须主动移除该线索、
看分数掉多少**。前者只证明线索存在，后者才证明它是否被依赖。

### 修掉的 5 个真bug（都是「不报错但结论错」类）
1. **train.py 用测试折做早停**（最致命）：每 epoch 在 `te` 上算 macro-F1 取 best
   → 测试集参与模型选择，指标系统性虚高。改为训练折内group-aware 切 12% 验证集。
2. **train.py 自己重做 StratifiedGroupKFold**，完全无视 D2 的双口径折号
   → 「泄漏幅度」根本无从算起。改为一律读 `fold_grouped`/`fold_stratified`。
3. **leakage_estimate 用 `enumerate(strat.values())`**：dict 插入顺序按 fold 轮次
   而非 i 升序 → 下标错位，算出「泄漏 0 张」的荒谬结果。改用 `strat.items()`。
4. **leakage_estimate 原指标恒为 5/5**（每折必然含多group，零信息量）→ 改为
   「多少 group 被拆散到多折 + 涉及多少张」。
5. **`mobilenetv3_small_100` 仓库名漏了 `.lamb_in1k`** → 一路404 到下载失败，
   而报错完全指不到原因。修法：仓库名一律从 timm 的 `pretrained_cfg["hf_hub_id"]` 读，
   本表只做白名单+ 反向自检（不一致当场炸）。

  更重要：它本来就不该无条件调—— **CNN 全卷积任意尺寸天然可用**，只有 ViT 需要改
  pos_embed。改为按骨干类型分派，ViT 走官方 `dynamic_img_size=True`。

### D3 最终结果（六格全齐，2 骨干 × 3 级别 × 双口径 × 2 种子 = 60 次评估）

| 级别 | EfficientNet-B0 (4.01M) | MobileNetV3-small (1.52M) | 最弱类 recall(B0) |
|---|---|---|---|
| L1 冻结+kNN | **98.44 ± 0.57%** | **98.16 ± 0.80%** | Off_platform 0.9339 |
| L2 冻结+线性探针 | **99.73 ± 0.06%** | **99.41 ± 0.70%** | Cracking 0.9936 |
| L3 全量微调 | **99.19 ± 0.98%** | **99.25 ± 0.48%** | Warping 0.9888 |

**核心结论（两骨干独立复现）**：
1. **L3 全量微调无增益**：B0 Δ=−0.54pp（σ_L2=0.06 vs σ_L3=0.98，L3 方差 16 倍）、
   MV3 Δ=−0.16pp。均值差完全落在噪声里 → 与文献一致（小数据微调破坏预训练特征）。
   **L2 零训练成本**（提特征 40s + 一次 LogReg 秒级），L3 需 20 次微调（12~13 min）换负收益。
   → **P1 映射层采用 L2**。
2. **两骨干完全等价**：L1/L2/L3 差 0.06~0.31pp，全部 <2pp。参数少 2.6 倍的 MV3 打平 B0
   → **本数据集已触及「ImageNet 预训练 + 轻量分类器」上限**，
   「算力不够所以上 Swin-T / 3B QLoRA」这个伪问题**现在有实测依据**。
3. **泄漏幅度六格全部 <1pp**（+0.08 / −0.18 / +0.40 / +0.30 / +0.14 / −0.82）→ 影响可忽略。
   三因：折叠仅 163/1912=8.5%；普通分层实际跨折 234 张=12.24%；
   **DINOv2 特征上跨类 max 0.9752 > 同类 P99 0.9569** → 这批近重复语义上并不「特别近」，
   kNN/线性探针靠它们作弊不了。
4. **两格出现负值**（B0 L2 −0.18、MV3 L3 −0.82）→ 分组后反而更高。**不是 bug**：
   分组同时消除了 stratified 下「最近训练邻同 group」的 11.61% 污染，两股力量方向相反。
   负值幅度在噪声内，**不宣称「分组能提升精度」**。

### 数字纪律：2pp 阈值的一处张力（记录待议）
L1 vs L2 差 1.29pp 判「等价」，但 L2 的 σ 仅 0.06pp（几乎无波动）→ 1.29pp 大概率是真实差异。
