### 结论（照实说）

1. ✅ **加正常类值得做**：误报 100%→0%，DC-02R 5 类仅 −0.08pp（N=200）。
2. 🔴 **但缺陷件识别仍塌缩**（top_share 98~99%）→ 这是**误报抑制**，**不是泛化修复**。

**落地**：N=200、阈值沿用 0.90、正常类命中直接返回不进 KB 映射。

### 🔴 本轮自踩 4 坑（全是"看起来对但静默算错"型）

1. **解包顺序错误（排查最久）**：`prB_full, _, _ = fit_predict(...)`，
   但返回是 `(pred, proba, pipe)`，第 0 个是**一维标签**不是概率。
   变量名带 `pr`(probability) 却装 pred → 下游 AxisError 报错指不到真因。
   → 教训：变量名要能自我说明装什么，`pr_` 前缀只留给 probability。
2. 🔴🔴 **类型陷阱（最隐蔽）**：`int(c) in full_classes`，
   而 `full_classes` 是**字符串列表**、`seen` 是**整数标签** → **恒 False**
   → 所有列被跳过 → proba 全零 → argmax 恒 0 → 表现为「预测全塌成 Warping」**且不报错**。
   🔴 为什么没早发现：我用 `full_classes=[0,1,2,3,4,5]`（整数）做单测，测试通过
   → **单测的输入和生产的输入不是同一个东西**。
   → 修法：按**位置** `aligned[:, int(c)] = proba[:, j]`，不做值比较。
3. **指标定义反向**：`normal_ok = (~answered & is_normal_truth)` 统计「拒答了正常件」，
   但正常件**正确判成No_error 时 answered=True** → 指标给 0%，
   **模型做对了指标说它错**。这类 bug 比数字错更危险（数字错会被发现，反向指标会让人照着做错决策）。
4. **阈值扫描用训练集内自评** → 必然 100%/100% 全平，等于没测 → 改用折外概率。

另：折文件键名是 **`fold_grouped`** 不是 `fold`（`fold_stratified` 是对照口径）。
A 组复现 99.68% 与历史 99.69% 一致 → 基线可信。

### 🔴 本项目最贵的一条教训

**D9 的 A/B 测了「正例」，没测「反例」。**
它验证了「正常件能被认出 100%」，**从未验证「缺陷件不会被一起认成正常」**——
而后者才是上线后最致命的。**少测的那一项让整个方案在线上反噬。**

🔴 纪律：任何「新增一类」或「加判别分支」的方案，必须**同时测两个方向**：
新类不被旧类吞、旧类不被新类吞。只测一个方向等于没测。

🔴 讽刺的是 `exp/d9_normal_class_design.md` **第七节 P1 探针已经设计了这个测试**
（「若缺陷件 5 类召回 <40% → 只能减少误报」），**但落地时没执行**。
**设计文档写了探针≠ 探针被跑了；A/B 实验的「通过」不能替代它。**

## 领域调研：单采集方式是行业通病，但有例外（2026-10-06）

用户问"是不是网上方法都是单采集方式训练的"。查证结论：

- **XJTU（Additive Manufacturing 2024）**正面研究域偏移：换环境/颜色/设备后 86%→44%，
  与 D8（99.73%→6.25%）同性质，我们落差更大是因为域差更大。证明 D8 负结果=领域公开问题，非我们的 bug。
- **例外（为泛化设计的数据集）**：
  - Cambridge Caxton（Brion & Pattinson 2022，DOI 10.17863/CAM.84082，CC BY 4.0）：
    **8 台打印机**、127 万张、喷嘴视角、变几何/颜色/光照，参数齐全（流量/速度/温度/Z offset）。

    类别与 KB 高度重合，可作第三域或泛化训练集。
  - Kaggle `early-detection-of-3d-printing-issues`：7 台打印机、喷嘴相机、二分类欠挤出。
  - 3D-ADAM（2025）：多传感器 RGB+3D 工业异常检测，仅 PLA。
